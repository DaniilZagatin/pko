# Frontend-support: редизайн дашборда «Клиентский путь»

Материалы для переноса на другой ноутбук изменений экрана дашборда:
клик по шеврону раскрывает описание этапа, карточки «Оценка» под ним, и
новая нижняя панель с тремя колонками (Общий вывод / Ключевые риски / Что
реализовать в первую очередь).

Всё лежит в `frontend-web/...` по тем же путям, что и в вашем проекте —
можно копировать файлы прямо поверх соответствующих в вашей копии
`frontend-web/`.

## 1. Скопировать файлы (заменить целиком)

Каждый файл ниже — **полное содержимое**, не диф. Копируйте целиком, ничего
вручную сливать не нужно.

Новые файлы (их не было — просто добавить):
- `frontend-web/src/components/dashboard/StatusDot.tsx`
- `frontend-web/src/components/dashboard/StageDescriptionPanel.tsx`
- `frontend-web/src/components/dashboard/StageEvaluationCard.tsx`
- `frontend-web/src/components/dashboard/ProjectSummaryPanel.tsx`

Изменённые файлы (заменить содержимое целиком тем, что в этой папке):
- `frontend-web/src/components/dashboard/Dashboard.tsx`
- `frontend-web/src/components/dashboard/Chevron.tsx`
- `frontend-web/src/components/dashboard/StatusLegend.tsx`
- `frontend-web/src/lib/types.ts` — **осторожно**: если у вас `types.ts` уже
  успел разойтись (например, там уже есть контракт для summary от вашего
  backend), не затирайте файл целиком — вручную добавьте только два блока:
  интерфейс `ProjectSummary` и поле `summary?: ProjectSummary` в
  `AnalysisResult` (см. этот файл, они в начале).

## 2. Удалить старые файлы

Эти два компонента больше не используются — их роль теперь выполняют
`StageDescriptionPanel` и `StageEvaluationCard`:
- `frontend-web/src/components/dashboard/StageComment.tsx`
- `frontend-web/src/components/dashboard/StageDescription.tsx`

Если `Dashboard.tsx` их больше не импортирует, а другие места на них не
ссылаются — можно удалять смело.

## 3. Добавить CSS

Это НЕ полный `globals.css` (у вас он мог уйти вперёд, например с тёмной
темой) — только небольшая добавка. Смотрите
`frontend-web/src/styles/globals.css.additions.css` в этой папке — там
ровно три правила и комментарий, куда их вставить в ваш существующий
`app/globals.css`.

### CSS-переменные, от которых всё это зависит

Новые компоненты используют `var(--green)`, `var(--amber)`, `var(--red)`,
`var(--purple)` (и их `-light` варианты), а также `var(--primary)`,
`var(--border)`, `var(--ring)`. Если они у вас уже есть в `:root` (скорее
всего да, это исходная палитра проекта) — ничего доделывать не нужно.
Если нет — их определения можно взять из этого же файла-примера
(`globals.css.additions.css` их не содержит, они не менялись).

## 4. Что нужно от backend

Нижняя панель (`ProjectSummaryPanel`) рендерится, только если в ответе
`GET /api/analyses/{id}` (тип `AnalysisResult` в `types.ts`) есть поле
`summary` вот такой формы:

```ts
interface ProjectSummary {
  conclusion: string;   // общий вывод — один абзац
  risks: string[];      // ключевые риски — список пунктов
  priorities: string[]; // что реализовать в первую очередь — список пунктов
}
```

То есть backend должен отдавать **три отдельных поля**, а не один общий
текст. Если у вас backend сейчас пишет один сплошной абзац через reporter —
его нужно либо научить возвращать JSON с этими тремя полями напрямую
(предпочтительно — надёжнее любого парсинга на фронте), либо явно решить,
что риски/приоритеты пока не показываются, и слать только `conclusion`
(тогда `risks`/`priorities` — просто пустые массивы, колонки останутся
пустыми, но не сломаются: `BulletList` ничего не рендерит на пустом
массиве).

Если поля `summary` в ответе вообще нет — панель просто не появится,
остальной дашборд работает как обычно.

## 5. Как проверить, что всё завелось

```bash
cd frontend-web
npm install   # если ещё не делали
npm run dev
```

Открыть экран анализа (`/analysis/[id]`) с любым готовым результатом:
- клик по шеврону — снизу должна появиться карточка «Описание этапа» с тем
  же цветом рамки, что у шеврона; повторный клик по тому же шеврону —
  карточка исчезает, и «Оценка» сдвигается вверх;
- карточки в «Оценка» — цветные, с точкой-статусом и подписью
  (Сделано/Частично/Не начато/Неясно) в заголовке;
- если backend прислал `summary` — под основной панелью появляется блок из
  трёх колонок с серыми вертикальными разделителями между ними (только на
  экранах шире ~768px, на мобильной ширине колонки складываются в столбец
  без разделителей).

Заодно стоит прогнать:
```bash
npm run build
npm run test
```

## Чего в этой папке нет и почему

На исходном ноутбуке в `frontend-web` есть ещё не закоммиченные правки под
тёмную тему (`ThemeToggle`, изменения в `layout.tsx`, `DashboardHeader.tsx`,
`AnalysisProgress.tsx` и др.) — они не имеют отношения к этому экрану и
сюда сознательно не включены, чтобы не тащить чужую незавершённую задачу.
